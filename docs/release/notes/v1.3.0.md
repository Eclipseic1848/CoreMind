## 简体中文

本说明对应 `1.3.0` 发布线，覆盖 #324–#333 的十项已验收合入修复。发布准备与源码 CI 不等于正式发布；公开可安装状态和最终资格以同版本、最终提交及准确制品证据为准。1.2.0 用户按[迁移指南](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/docs/migrations/1.2-to-1.3.zh-CN.md)升级。

### 关键亮点

- 保护框架持久状态，并让并行失败、显式退出与 Web 错误按各自生命周期收尾。
- 将 Workflow 步骤结果与模型历史分离，解析 Python 延迟注解，并补全 Diff 内容变化检测。
- 保留可持久查询的 v2 启动错误身份，按所选 Provider 进行离线 doctor 诊断。

### 本版本完整变更日志

本节记录 `1.3.0` 发布准备范围，包含 #324–#333 已验收合入的十项修复；不表示已经公开发布。详见[固定双语发布说明](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/docs/release/notes/v1.3.0.md)与[1.2→1.3 迁移指南](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/docs/migrations/1.2-to-1.3.zh-CN.md)。

#### 安全修复

- **框架状态保护：** 统一授权按 canonical 目标保护框架管理的持久状态，普通业务工具不能通过 `ask`、`assisted`、`full` 或显式 allow 改写这些状态。现存多硬链接文件的普通工具写入也会被拒绝；合法业务文件和宿主维护接口保留原职责。这是路径保护，不是任意宿主代码的 OS 沙箱。 ([#324](https://github.com/Eclipseic1848/CoreMind/issues/324))
- **开发构建依赖：** 将 Vitest 测试链的 Vite 固定为 `8.2.4`，仅将 VitePress `1.6.4` 子树的 Vite 覆盖为 `6.4.4`，修复编辑器启动相关漏洞；不引入预发行文档框架，也不新增风险豁免。变更限于开发/文档构建依赖，不改变 Runtime 权限或沙箱边界。 ([#350](https://github.com/Eclipseic1848/CoreMind/issues/350))

#### 缺陷修复

##### Runtime 与 Workflow

- **并行终止与准入：** 普通 `parallel` 子步骤首次失败或暂停时，取消同组其他步骤并等待收尾，保留首个错误；Run 结束后不再准入新模型调用。已开始操作保留收据，取消不等于回滚；全成功仍按声明顺序聚合。 ([#325](https://github.com/Eclipseic1848/CoreMind/issues/325))
- **步骤输出边界：** Workflow `prompt`/`call` 保留同一 Session 历史作为模型上下文，但步骤输出、`saveAs`、后续插值与 transcript 只包含本步骤新增的 assistant 文本，不重复历史回答。 ([#327](https://github.com/Eclipseic1848/CoreMind/issues/327))
- **v2 启动错误身份：** 已接受 Run 的 Runtime 初始化失败按共享错误分类持久化稳定错误码、对应终态与安全消息，供 `query`/`events` 查询，不再统一改为 `agent_failed`。未知异常以 `unclassified_error` 保守暂停并要求人工审计，不公开凭据或原始堆栈，也不表示可直接恢复。 ([#329](https://github.com/Eclipseic1848/CoreMind/issues/329))

##### Python 工具桥

- **延迟参数注解：** v1 `@client.tool` 自动 Schema 可解析 future/字符串形式的 `int`、`str`、`bool` 和既有支持的容器注解；无法解析的前向引用明确要求显式 `parameters`。保留 Node 侧先转换再校验的既有规则，转换后仍未通过 Schema 的参数在 callable 执行前拒绝；显式 Schema 兼容，复杂 typing 支持范围不扩大。 ([#326](https://github.com/Eclipseic1848/CoreMind/issues/326))

##### 评测

- **Diff grader：** `preserveExisting: false` 只关闭既有脏内容保护，`allowedPaths`、`forbiddenPaths`、`requiredPaths`、`maxChangedFiles` 仍按基线与终态的状态或内容差异执行。状态和内容均未变化的既有脏文件不计，原 untracked 文件删除计入变化；原 stage/unstage 计数及默认 `true` 保护不变。 ([#328](https://github.com/Eclipseic1848/CoreMind/issues/328))

##### Web 工具

- **响应正文收尾：** `web-fetch`/`web-search` 遇非 2xx 或正文读取失败时，等待正文取消/释放的清理尝试结束后才结算本地网络活动；清理异常保留原 HTTP/读取错误。成功、取消、权限与网络策略不变，`web-fetch` 原 2 MiB 正文上限保留。 ([#330](https://github.com/Eclipseic1848/CoreMind/issues/330))

##### CLI

- **readline 显式退出：** `/exit`、`!exit` 与 TUI 一致，先请求取消活动 Run 并等待收尾；普通管道 EOF 仍让已开始的回答自然完成。空闲退出、审批及 MCP 登录等待的既有行为保持，取消不回滚已开始工具副作用。 ([#331](https://github.com/Eclipseic1848/CoreMind/issues/331))
- **doctor 凭据策略：** 有配置时复用所选 Provider 的既有校验，合法匿名/Header-only 自定义端点不要求无关 API key；显式凭据缺失仍失败，内置鉴权要求不放宽。无配置通用诊断保留；检查不加载项目脚本、不发 Provider 请求，通过不代表凭据有效、真实连通或认证。 ([#332](https://github.com/Eclipseic1848/CoreMind/issues/332))

#### 文档

- **安全策略版本状态：** 双语 SECURITY 支持表链接最新正式 Release，准确标明 1.2.0 已发布与既有安全加固已交付；保留 `0.3.1` 重大安全问题例外、私密披露方式及原安全边界，不把本轮新保护归为旧版能力。 ([#333](https://github.com/Eclipseic1848/CoreMind/issues/333))

- **发布材料与验证：** 同步 1.3.0 包版本、模块与 TTY 模板，冻结随包 Worker，补充双语迁移和发布材料，并把新版本固定正文纳入既有回归；正式发布仍须完成最终提交的严格资格与公开回装。 ([#334](https://github.com/Eclipseic1848/CoreMind/issues/334))
- **安装与导航一致性：** 同步双语快速入门、CLI/配置指南、npm/Python 包说明及文档导航的 1.3.0 安装目标、当前资格和 1.2→1.3 迁移入口，保留历史指南与原安全、信任和认证边界。 ([#346](https://github.com/Eclipseic1848/CoreMind/issues/346))

#### 兼容与发布边界

Config/Protocol 版本不升级，保留 Config v2/v3、Protocol v1/v2 和统一 Node Runtime。`ToolPolicy` 构造选项新增可选 `protectedPaths` 保护条目，`authorize()` 的 `identity` 新增可选 `signal?: AbortSignal`，既有调用保持兼容；SDK 与 bundled Worker 须同步升级并保留原指纹检查。正式发布仍需绑定最终 main 提交、当前版本、Runtime/Worker 与准确制品的严格 Provider、双平台工程/稳定性/覆盖率/真实 PTY，以及公开下载和回装证据。旧版本认证、历史例外与单项 CI 不能替代本轮资格；外部副作用仍需人工核对。

### 兼容、升级与回滚

运行要求继续为 Node.js ≥ 22.19、Python ≥ 3.10，Git 工具要求 Git ≥ 2.36；Windows 与 Linux 的原支持范围不变。

升级前停止旧进程并备份配置、Session、RunState 与 Checkpoint。核对新拒绝边界、步骤输出、错误分类与退出行为后再切换业务。回滚时停止新进程，将程序、SDK、Worker 一起恢复为已发布 1.2.0，并恢复升级前状态备份；不要并发写入同一状态目录。恢复本地状态不撤销已经发生的外部操作，started/unknown Effect 仍需人工核对。

### 验证与限制

十项修复的定向回归和合入 CI 不能替代 1.3.0 发布资格。发布准备 PR 先完成工程、Python、文档和打包门；合入后在冻结 main 上完成同版本、最终提交、Runtime 摘要与 bundled Worker 绑定的严格 Provider、Windows/Linux 稳定性、覆盖率和真实 PTY，再执行正式发布及公开制品逐字节下载/回装验证。没有这些证据时不得标记已认证或已发布，也不得复用 1.2.0 的认证、运行号或豁免。

本轮不提供新的 OS 沙箱、远端执行能力、自动副作用回滚或新的搜索正文大小合同。真实外部 OAuth/MCP 互通及全局成对性能收益尚未认证。版本、Tag、清单与制品身份必须一致；发布后恢复只能复用原不可变制品。真实依赖与许可证义务保持，见目标发布 Tag 的[第三方声明](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/THIRD_PARTY_NOTICES.md)和[许可证](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/LICENSE)；该 Tag 须在实际发布时存在。

## English

These notes describe the `1.3.0` release line and the ten accepted, merged fixes in #324–#333. Release preparation and source CI do not establish formal publication; public installability and final qualification require evidence for the same version, final commit, and exact artifacts. Users on 1.2.0 should follow the [migration guide](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/docs/migrations/1.2-to-1.3.en.md).

### Key highlights

- Protect framework persistent state and settle parallel failures, explicit exit, and Web errors through their existing lifecycles.
- Separate Workflow results from model history, resolve deferred Python annotations, and complete Diff content-change detection.
- Retain queryable, persisted v2 startup-error identity and run offline doctor diagnostics for the selected Provider.

### Complete changelog for this version

This section records `1.3.0` release preparation and the ten accepted, merged fixes in #324–#333; it does not establish public publication. See the [fixed bilingual release notes](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/docs/release/notes/v1.3.0.md) and [1.2→1.3 migration guide](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/docs/migrations/1.2-to-1.3.en.md).

#### Security Fixes

- **Framework-state protection:** unified authorization protects framework-managed persistent state by canonical target. Ordinary business tools cannot bypass it through `ask`, `assisted`, `full`, or an explicit allow. Ordinary tool writes to existing multiply hard-linked files are also rejected; legitimate business files and host maintenance interfaces retain their roles. This is path protection, not an OS sandbox for arbitrary host code. ([#324](https://github.com/Eclipseic1848/CoreMind/issues/324))
- **Development/build dependencies:** pin Vite in the Vitest test chain to `8.2.4` and override Vite to `6.4.4` only within the VitePress `1.6.4` subtree to fix editor-launch vulnerabilities. No prerelease documentation framework or new risk exception is introduced. The change is limited to development/documentation build dependencies and does not change Runtime permissions or sandbox boundaries. ([#350](https://github.com/Eclipseic1848/CoreMind/issues/350))

#### Bug Fixes

##### Runtime and Workflow

- **Parallel termination and admission:** the first failure or pause in an ordinary `parallel` substep cancels its siblings and waits for settlement while preserving the first error. No new model calls are admitted after the Run ends. Started operations retain receipts; cancellation is not rollback. All-success results still aggregate in declaration order. ([#325](https://github.com/Eclipseic1848/CoreMind/issues/325))
- **Step-output boundaries:** Workflow `prompt`/`call` retains the same Session history as model context, while step output, `saveAs`, subsequent interpolation, and transcript contain only assistant text newly produced by that step, without repeating earlier replies. ([#327](https://github.com/Eclipseic1848/CoreMind/issues/327))
- **V2 startup-error identity:** Runtime initialization failures after Run acceptance persist the shared classification's stable code, corresponding outcome status, and safe message for `query`/`events`, rather than replacing every failure with `agent_failed`. Unknown exceptions pause as `unclassified_error` and require human audit, without exposing credentials or raw stacks or establishing that direct resume is safe. ([#329](https://github.com/Eclipseic1848/CoreMind/issues/329))

##### Python tool bridge

- **Deferred parameter annotations:** v1 `@client.tool` automatic schemas resolve future/string annotations for `int`, `str`, `bool`, and existing supported containers. Unresolvable forward references explicitly require `parameters`. Existing Node conversion still precedes validation; arguments that remain invalid are rejected before callable execution. Explicit schemas remain compatible without expanding complex typing support. ([#326](https://github.com/Eclipseic1848/CoreMind/issues/326))

##### Evaluation

- **Diff grader:** `preserveExisting: false` only disables protection of existing dirty content. `allowedPaths`, `forbiddenPaths`, `requiredPaths`, and `maxChangedFiles` still use baseline-to-final status or content differences. Dirty files with unchanged status and content do not count; deleting a file untracked at baseline does. Existing stage/unstage counting and default `true` protection remain unchanged. ([#328](https://github.com/Eclipseic1848/CoreMind/issues/328))

##### Web tools

- **Response-body settlement:** on non-2xx responses or body-read failures, `web-fetch`/`web-search` await body cancellation/release cleanup attempts before settling local network activity. Cleanup failures preserve the original HTTP/read error. Success, cancellation, permissions, network policy, and the existing `web-fetch` 2 MiB body limit remain unchanged. ([#330](https://github.com/Eclipseic1848/CoreMind/issues/330))

##### CLI

- **Explicit readline exit:** `/exit` and `!exit` match the TUI by requesting active-Run cancellation before waiting for cleanup. Ordinary piped EOF still lets an already-started response finish naturally. Existing idle-exit, approval-wait, and MCP-login-wait behavior remains; cancellation does not roll back started tool effects. ([#331](https://github.com/Eclipseic1848/CoreMind/issues/331))
- **Doctor credential policy:** configured diagnostics reuse the selected Provider's existing checks. Legitimate anonymous/Header-only custom endpoints require no unrelated API key; explicit missing credentials still fail, and built-in authentication requirements are not relaxed. General diagnostics without a config remain. Checks neither load project scripts nor send Provider requests; passing does not prove credential validity, connectivity, or certification. ([#332](https://github.com/Eclipseic1848/CoreMind/issues/332))

#### Documentation

- **Security-policy version status:** bilingual SECURITY tables link to the latest official Release and identify 1.2.0 and existing hardening as shipped. The `0.3.1` critical-security exception, private disclosure process, and existing safety boundaries remain; this round's new protections are not attributed to older releases. ([#333](https://github.com/Eclipseic1848/CoreMind/issues/333))

- **Release materials and validation:** synchronize 1.3.0 package versions, module and TTY templates, freeze the bundled Worker, add bilingual migration and release materials, and include the new fixed notes in existing regression checks. Publication still requires final-commit strict qualification and public reinstall checks. ([#334](https://github.com/Eclipseic1848/CoreMind/issues/334))
- **Installation and navigation consistency:** align bilingual quickstarts, CLI/configuration guides, npm/Python package descriptions, and documentation navigation with the 1.3.0 installation target, current qualification, and 1.2→1.3 migration, retaining historical guides and existing safety, trust, and certification boundaries. ([#346](https://github.com/Eclipseic1848/CoreMind/issues/346))

#### Compatibility and publication boundaries

Config/Protocol versions do not change: Config v2/v3, Protocol v1/v2, and the unified Node Runtime remain. `ToolPolicy` gains optional `protectedPaths` constructor entries, and the `identity` argument of `authorize()` gains optional `signal?: AbortSignal`; existing calls remain compatible. Upgrade the SDK and bundled Worker together and retain existing fingerprint checks. Formal publication still requires strict Provider, both-platform engineering/stability/coverage/real PTY, and public download/reinstall evidence bound to the final main commit, current version, Runtime/Worker, and exact artifacts. Older certification, historical exceptions, and individual CI runs do not qualify this release; external effects still require human reconciliation.

### Compatibility, upgrade, and rollback

Requirements remain Node.js ≥ 22.19 and Python ≥ 3.10, with Git ≥ 2.36 for Git tools. Existing Windows and Linux support is unchanged.

Stop old processes and back up configuration, Sessions, RunState, and Checkpoints before upgrading. Check the rejection boundaries, step outputs, error classifications, and exit behavior before switching business use. To roll back, stop new processes, restore programs, SDKs, and Worker together to the published 1.2.0 release, and restore pre-upgrade state backups. Never run concurrent writers against the same state directory. Local restoration does not undo external operations; started/unknown Effects still require human reconciliation.

### Verification and limitations

Targeted regressions and merge CI for the ten fixes do not replace 1.3.0 release qualification. The preparation PR first completes engineering, Python, documentation, and packaging gates. After merge, freeze main and obtain strict Provider, Windows/Linux stability, coverage, and real PTY evidence bound to that version, final commit, Runtime digest, and bundled Worker before publication and public exact-artifact download/reinstall checks. Without that evidence, do not mark the release certified or published or reuse 1.2.0 certification, run IDs, or exceptions.

This round adds no OS sandbox, remote execution capability, automatic effect rollback, or new search-body size contract. Real external OAuth/MCP interoperability and global paired performance gains are not certified. Version, tag, manifest, and artifact identities must agree; publication recovery reuses the original immutable artifacts. Actual dependency and license obligations remain; see the target tag's [third-party notices](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/THIRD_PARTY_NOTICES.md) and [license](https://github.com/Eclipseic1848/CoreMind/blob/v1.3.0/LICENSE). That tag must exist at actual publication.
