## 简体中文

CoreMind 2.1.0 将知识、Hindsight 记忆、Skill、工具和本体拆成可独立选用的能力。业务方从自己的项目开始，只配置需要的服务、数据和权限。`document-assistant` 继续提供组合参考。[五域交付记录](https://github.com/Eclipseic1848/CoreMind/pull/424)

- **创建项目。** `coremind create . --runtime-only` 只生成一个模型和一个 Agent 的最小配置，已有 `coremind.yaml` 会保留。CLI/YAML、TypeScript、Python 同步与异步共用同一运行合同。
- **知识。** `coremind-knowledge-mcp` 0.1.0 提供独立服务。宿主保管原文、索引和撤回清单，读者可通过 MCP 检索并解析带来源、版本和位置的引文。
- **记忆。** `coremind-memory-mcp` 0.1.0 连接宿主的 Hindsight 和 PostgreSQL。宿主使用管理身份写入、更正和遗忘，Agent 使用独立的只读身份跨会话召回。
- **Skill 与工具。** `coremind-templates` 提供 `coremind-skill-install`，可按审核过的 Git 提交安装和回退 Skill。工具可由 SDK 单独注册，也可绑定 MCP。更换工具实现或移除授权后，可在新 Runtime 中单独复验。
- **本体。** `coremind-ontology-mcp` 0.1.0 从外部目录加载 RDF 模型和 SHACL 约束。业务动作须另配处理器、写凭据和持久回执。遇到结果未知的动作，宿主先核对业务记录。
- **Provider。** `providers` 和 `create` 列出可配置入口并给出在线矩阵。按目标版本、提交和 Runtime 摘要查看真实认证记录。[认证矩阵](https://github.com/Eclipseic1848/CoreMind/blob/main/docs/providers/README.zh-CN.md)

发布清单包含 13 件制品，分别为 8 个 npm tarball、1 个 SDK wheel、3 个独立服务 wheel 和 1 个源码 ZIP。公开回装逐件与正式构建核对 SHA-256。

五域独立交付的仓库外消费者通过 49 项检查，覆盖四个客户端入口、空白 Runtime、单项、组合和移除。模型使用确定性夹具，三个 MCP 服务从安装件运行。业务方仍需用自己的资料、身份和模型验证结果，并单独确认生产容量和外部动作回执。版本发布资格和公开回装以同一构建的记录为准。[五域建设与验收](https://github.com/Eclipseic1848/CoreMind/blob/main/docs/guide/06-capability-construction.md) · [迁移与回退](https://github.com/Eclipseic1848/CoreMind/blob/main/docs/migrations/2.0-to-2.1.zh-CN.md) · [第三方声明](https://github.com/Eclipseic1848/CoreMind/blob/main/THIRD_PARTY_NOTICES.md)

## English

CoreMind 2.1.0 lets application teams select knowledge, Hindsight memory, Skills, tools and ontology independently. Start in your own project and supply the services, data and permissions your agent needs. `document-assistant` remains a composition example. [Implementation record](https://github.com/Eclipseic1848/CoreMind/pull/424)

- **Project creation.** `coremind create . --runtime-only` generates a minimal configuration with one model and one agent and preserves an existing `coremind.yaml`. CLI/YAML, TypeScript and synchronous and asynchronous Python share the Runtime contract.
- **Knowledge.** The independent `coremind-knowledge-mcp` 0.1.0 service retrieves and resolves citations with source, version and location over MCP. The host owns source documents, indexes and withdrawal records.
- **Memory.** `coremind-memory-mcp` 0.1.0 connects to the host's Hindsight service and PostgreSQL. The host retains, corrects and forgets facts with a management identity. The agent recalls facts across sessions with a separate read identity.
- **Skills and tools.** `coremind-templates` supplies `coremind-skill-install` to install a reviewed Git commit or roll back a Skill. Register a tool with the SDK or bind an MCP operation. Verify a replacement implementation or removal of access in a fresh Runtime.
- **Ontology.** `coremind-ontology-mcp` 0.1.0 loads RDF models and SHACL constraints from an external directory. Actions require a handler, write credentials and durable receipts. Reconcile uncertain outcomes with the business system.
- **Providers.** `providers` and `create` list configurable entries and link to the online matrix. Look up certification by target version, commit and Runtime digest. [Certification matrix](https://github.com/Eclipseic1848/CoreMind/blob/main/docs/providers/README.en.md)

The release inventory comprises 13 artifacts: eight npm tarballs, one SDK wheel, three independent service wheels and one source ZIP. Public reinstall checks compare each SHA-256 with the release build.

The independent component implementation passed 49 external consumer checks across four client entry points, the Runtime baseline, single capabilities, combinations and removal. The checks used a deterministic model fixture and three MCP services running from installed packages. Production capacity and external business action outcomes are not certified by these checks. Validate your data, identities and model in the target deployment. Release qualification and public reinstall are recorded against artifacts from the same build.
