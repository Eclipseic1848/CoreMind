# 日常工程 CI 与候选资格分开运行

CoreMind 将每个 PR/main 必跑的快速工程门与 nightly/manual 候选资格门分开：前者在约 20～30 分钟内完成构建、类型、核心确定性测试、安全、文档、关键双平台行为和 Python 一致性，并作为 `main` 的必需检查；后者运行三连稳定性、完整 Coverage、打包、TTY、重型故障矩阵、严格 RC 和真实 Provider 认证。该拆分不删除测试，`0.7.0` 发布候选仍必须通过两层全部门禁；普通 CI 不因缺少人工凭据或 Provider 证据变红。

`0.7.0` 的严格候选 Provider 请求在 HTTP 响应前网络超时后，维护者批准了一次性、精确绑定的网络例外。该例外只改变本版本候选资格的外部 Provider 结论，不改变工程 CI 与候选矩阵分层，不删除双平台、打包、TTY 或故障测试，也不建立后续版本的通用跳过路径。
