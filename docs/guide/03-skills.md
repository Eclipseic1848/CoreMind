# 技能指南

技能（skills）为 agent 提供专业 SOP，例如审查清单、写作模板和翻译纪律。内置技能和旧 `README.md` 仍全文进入稳定提示前缀；1.1 开发线新增 `SKILL.md` 索引与按需正文加载。实际效果仍需用场景评测验证。

## 为什么需要技能

只写 systemPrompt 的 agent 往往缺少具体的领域流程。配了技能后，可以给模型明确的工作步骤和输出要求：

- 代码审查 → 必须按检查清单逐项核对，输出 `[高]/[中]/[低]` 分级结论
- 周报 → 固定三节结构（本周工作/风险与阻塞/下周计划）
- 翻译 → 术语全文一致、格式不破坏、自检清单

技能还是**可复用资产**：一个技能配给多个 agent。修改文件后，重新启动 CLI 或重新创建 Runtime 才会加载新内容；已开始的 Run 不会因此自动改变。

## 使用：三行配置

```yaml
agents:
  reviewer:
    systemPrompt: 你是资深代码审查专家。
    skills:
      - code-review          # 注入代码审查技能
```

## 内置技能

| 技能 id | 名称 | 作用 |
|---|---|---|
| `code-review` | 代码审查 | 按 SOP 审查：正确性/安全/性能/可维护性，输出分级结论 |
| `weekly-report` | 周报撰写 | 按 SOP 生成周报：收集维度/结构模板/价值导向写作 |
| `translation` | 翻译 | 术语一致/格式保持/自检清单 |

写错技能 id 不报错——会告警提示并忽略（可用列表会显示在告警里）。

## 技能与模板的区别

| | 模板 | 技能 |
|---|---|---|
| 是什么 | 完整可跑的配置（agent + workflow） | 可复用的专业能力（SOP 文本） |
| 怎么用 | `coremind create --template <id>` | `skills: [<id>]` 注入任意 agent |
| 粒度 | 整个项目 | 单个 agent 的能力增强 |

部分模板已预配技能（如 code-reviewer 自带 code-review 技能），开箱即用。

## 自定义技能

内置技能之外，可以在**配置文件所在目录**（SDK 的 `configDir`）的 `skills/` 下放自己的技能。目录名是技能 id，配置仍用 `skills: [<id>]`。只解析显式选择的 id，不扫描祖先目录或发现远程技能。

```
my-agent/
├── coremind.yaml
└── skills/
    └── legal-review/          # 技能 id：legal-review
        ├── SKILL.md           # 标准技能：索引和按需正文
        └── README.md          # 旧格式可单独使用，全文进入前缀
```

```yaml
# coremind.yaml
agents:
  reviewer:
    skills:
      - legal-review           # 引用自定义技能
```

同 id 时内置优先。项目目录中同时存在 `SKILL.md` 和 `README.md` 时，选择 `SKILL.md` 并告警；标准文件损坏会拒绝运行，不回落到 README。真正缺失的 id 仍告警并忽略。只有 README 时保持原全文注入方式和内置先、项目后的顺序。

### 标准技能文件

`skills/legal-review/SKILL.md` 使用 YAML frontmatter，名称和描述须为非空字符串；支持中文和多行描述：

```markdown
---
name: 合同审查
description: |
  核对付款、交付和责任条款。
  输出风险和待确认事项。
---

先读取项目提供的合同与业务规则，再逐项核对条款；缺少依据时标记待确认。
```

名称用于展示，不能作为别名调用。不同 id 使用相同名称会告警；重复选择同一标准 id 不重复生成索引。

首次模型请求只包含已授权标准技能的 id、名称、描述和正文 SHA-256。当前 Agent 可调用 `load_skill({"id":"legal-review"})` 获取冻结正文；入口不接受路径或其他 Agent 参数，未选 id 无法加载。调用仍经过 ToolPolicy、审批和预算，技能中的指令不增加文件、网络或进程权限。同名自定义工具会在标准技能启用时被拒绝。

已成功加载且正文仍在最终模型工作集时，再次调用返回短引用；正文被压缩移出后，可重新加载同一冻结正文。引用、用户自述或历史加载标记不代表正文仍在当前请求中。加载结果随正常工具消息进入预算、实际请求与重建，不向稳定前缀再次追加全文。

### 大小、冻结和恢复

- 单个项目技能源文件最多 256 KiB，包含 frontmatter；每次解析结果和全部 Agent 的冻结快照分别最多 2 MiB，按 JSON 序列化后的 UTF-8 字节计算，超限明确失败。
- 目录和文件按 canonical path 校验边界，越界链接、无效 UTF-8、读取权限错误及读取期间身份变化都会失败。ID 不能表达任意路径。
- 正文保留去除 frontmatter 后的实际 UTF-8 字节与换行；正文和快照 SHA 均为原始 64 字符十六进制字符串，没有 `sha256:` 前缀。
- 启用标准技能时，创建 Runtime 会冻结所选内容；之后改文件不影响该 Runtime 的 Run 或其 Child。重新创建 Runtime 才加载新内容。恢复已有标准技能 Run 使用原 start 快照，不重读已修改或删除的源文件；损坏快照或不匹配选择会拒绝恢复，原有配置和恢复安全门仍适用。

原始 RunStore 是受信宿主的数据，含冻结正文和加载事实；公开投影、Worker 事件和遥测导出会剥离这些私有旁挂字段。已加载正文仍可能存在于正常会话、模型请求或业务输出中。SHA 用于一致性校验，不是签名，也不防止持有原始 Store 的宿主自行改写数据。

关闭 Session 不等于恢复完整对话。冻结快照和加载事实可重建技能结果；完整请求重建仍依赖已持久化的会话条目、压缩记录和对应前缀。Store 的耐久边界保持原合同。

（"配置文件所在目录"的含义见 [CLI 使用指南](05-cli-usage.md#3-在哪里运行目录规则新手最容易困惑的部分)。）

## 技能生态

技能是**可复用的内容资产**：把 `skills/<id>/README.md` 或 `SKILL.md` 交给受信任的项目，由对方审查后显式配置。CoreMind 不自动加载相邻 references、执行技能脚本、安装依赖、远程同步或提供技能市场。
