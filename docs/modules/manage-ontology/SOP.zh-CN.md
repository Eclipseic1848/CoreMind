# 可选本体开发 SOP

从一个业务问题开始。记录业务方给出的字段解释、动作执行者、成功依据与需要人工确认的样例。冻结模型、实例、形状、映射和动作文件；保留模型版本、模型摘要、整包摘要及映射版本。每项检查记录使用的入口、输入、观察结果及代码或资料版本。

| 检查 | 输入与判据 |
| --- | --- |
| 06.01 对象与关系 | 查询已知实例，核对类型、属性、出向关系及目标 IRI；查不存在的资源。再提供一套更名的类型、关系和实例，验证相同接口无需修改。 |
| 06.02 概念对齐 | 两个来源编号指向同一确认对象；检查状态码、同义字段和单位换算，并核对原始值及映射版本。重名候选、冲突字段或未登记编码须返回 `needs_confirmation` 和空映射图。 |
| 06.03 约束校验 | 用同一版本测试合规实例、缺复核人、错误属性类型和无约束的图；核对 `conforms`、`violates` 与具体规则覆盖。损坏模型或中断校验引擎时应观测到 `unavailable`。归档引起违规的对象、属性和规则。 |
| 06.04 动作语义 | 检查 `publish` 的目标类型、前态、预期后态。目标错误、业务前提失败、只读令牌或工具政策拒绝时，执行器调用数为零。接入写处理器后核对回执中的目标、请求和状态。 |
| 结果未知 | 模拟处理器已受理后断连以及回执状态未达预期。记录 `unknown` 并核查执行器次数；相同请求的记录可复读，替换请求标识也不得绕过待核对的效果。 |
| 入口一致 | CLI+YAML、TypeScript、Python 同步、Python 异步分别运行。启用时得到同一对象和版本；停用时无需本体连接；模型装载失败时返回校验不可用。另记传输不可达的错误阶段，避免把无法连接误报为业务违规。 |

从仓库根目录运行下面的检查。四入口脚本自建本地模型夹具与临时本体服务。设置 `COREMIND_ONTOLOGY_PYTHON` 指向已装依赖的 Python 3.12 解释器；Node 工作区、Python SDK 与 Worker 的准备步骤见示例。

```sh
python -B -X utf8 -m unittest discover -s examples/modules/manage-ontology -p "test_*.py"
node examples/modules/manage-ontology/acceptance.mjs
npm run check:modules
```

将四入口输出、动作实际调用次数和模型／映射版本附到验收记录。更换模型或动作规则后，用相同输入重测旧版与新版，并核对差异是否来自预期改动。[可运行示例](../../../examples/modules/manage-ontology/README.zh-CN.md) · [模块清单](module.yaml)

## 独立 wheel 验收

在仓库外的空白业务目录和新 Python 环境中仅安装本体组件。验收 0.1.0 时运行 `python -m pip install coremind-ontology-mcp==0.1.0`。记录安装来源、组件版本与摘要。隔离源码目录，加载项目提供的模型目录，用标准 MCP 客户端完成一次对象查询、一次约束违规和一次只读令牌执行拒绝。再用同一组件切换第二套模型，确认返回模型版本与摘要随资产变化。

首个安装件用 2.0.0 源码服务作升级基线。以副本演练升级和回滚，复核原有对象 IRI、映射、SHACL 结果和业务回执，确认未决写操作不会重放。移除绑定后，业务宿主其余功能应继续运行。保留模型和回执后，再卸除专用服务环境。

0.1.0 的仓库外验收使用全新环境和公开 MCP 协议实际读取模型、验证三类来源记录、测试读写令牌与动作前提。业务样例提交事务后故意终止服务，升级模型再回滚，验证原请求仍未知、新 ID 仍拒绝，业务表只有两笔实际回执。[复跑入口](../../../examples/modules/manage-ontology/README.zh-CN.md)

## 备份与隔离恢复验收

按照[最小部署与恢复示例](../../../examples/modules/manage-ontology/deployment/README.zh-CN.md)在两套独立环境安装公开 wheel。验证经授权的 `/health` 与已知对象查询。执行业务写入样例后停止两边写入，再保存模型、处理器、组件回执和业务 SQLite 的同点备份，并恢复到新目录。恢复后核对已完成请求回读、未知请求保持未知、新 ID 仍被阻断、额外业务处理器调用为零。用原运行环境再次打开恢复目录，复查同样的摘要和回执。记录两次启动耗时以及备份字节数。同版本环境替换和模型版本回退分别记录。

## P3 开发验收

用[离线效果回归](../evaluate-agents/SOP.zh-CN.md#五项可选能力效果回归)保存拒绝、完成、重放、未知和新请求被阻断时的实际回执。核对请求 ID、目标、原状态和结果。重复请求须返回同一业务回执。

- Windows Python 3.12 和 Linux 容器 Python 3.13 各通过 15 项测试。覆盖两套模型切换、字段归一、真实 SHACL 报告和动作回执。
- Windows 四入口在启用、停用和模型损坏三种状态下通过 12/12。额外验证只读令牌拒绝写入、权限拒绝、草稿前置失败、允许后读回状态和同请求 ID 回放。
- 本体服务整体断连时模型请求数为 0。业务回执缺失时，Runtime 保存 `started` 和 `unknown` 效果事实，拒绝用新请求重复写入同一目标。
- 跨会话组合验证保存了三份摘要，分别覆盖版本引用、已确认表格偏好和草稿发布拒绝，以及偏好更正和撤回后的引用。联合用例使用实际服务适配器、工具和本体引擎，索引、记忆存储和模型由确定性夹具提供。
