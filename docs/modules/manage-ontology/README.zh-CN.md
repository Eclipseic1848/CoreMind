# 可选本体与业务动作

业务方可以用自己的词汇表定义对象、属性和关系，统一来源记录的含义，并说明什么条件下可以执行一个动作。例如，资料室可以把两个目录中的编号对应到同一份资料，检查它是否有复核人，再决定是否允许发布。

CoreMind 2.0.0 的源码入口继续兼容。2.1.0 候选支持单独安装本地 `coremind-ontology-mcp` 0.1.0 wheel，使用自己的模型目录，在空白项目中只绑定只读 MCP 工具。组件 wheel 使用独立版本，业务资产由项目方保管。[组件包](../../../components/ontology/README.md)

| 图谱能力 | 模块提供的能力 |
| --- | --- |
| 06.01 对象与关系建模 | 从 Turtle 加载领域词汇与实例，查询类型、属性和出向关系。 |
| 06.02 业务概念对齐 | 按业务方的版本化映射归一标识、字段、单位和编码，保留原始记录与歧义。 |
| 06.03 规则约束与校验 | 用 pySHACL 执行 SHACL Core 校验，返回违规对象、属性、规则与说明。 |
| 06.04 业务动作语义 | 宿主声明目标类型、前态、后态和处理器；执行时复核权限、前置条件与业务回执。 |

默认项目无需绑定本体。CLI、TypeScript、Python 同步和异步入口可通过同一个 Streamable HTTP MCP 服务使用业务模型。接入步骤见[指南](GUIDE.zh-CN.md)，可运行命令见[示例](../../../examples/modules/manage-ontology/README.zh-CN.md)，验收判据见[开发 SOP](SOP.zh-CN.md)。
