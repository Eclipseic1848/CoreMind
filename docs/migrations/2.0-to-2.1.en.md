# Upgrade from CoreMind 2.0.0 to 2.1.0

[简体中文](2.0-to-2.1.zh-CN.md)

The 2.1.0 CLI and TypeScript and Python SDKs share one Runtime. The Python wheel includes the matching Worker. Install and upgrade knowledge, Hindsight memory, and ontology independently. Each starts at public version `0.1.0`. [2.1.0 release](https://github.com/Eclipseic1848/CoreMind/releases/tag/v2.1.0) · [Release artifacts and verification](https://github.com/Eclipseic1848/CoreMind/issues/427)

## Upgrade the clients

1. Back up the application lockfile, configuration, run state, and business data. Verify the upgrade in a separate application directory before moving the active project. Use Node.js 22.19 or later.
2. Pin the CLI and TypeScript SDK in your npm project. Run `npm init -y` first in a fresh directory.

   ```sh
   npm install --save-exact coremind-cli@2.1.0 coremind-ai@2.1.0
   ```

3. If you need the Python SDK, install it by name from PyPI in a fresh Python 3.10+ environment. Leave `COREMIND_WORKER_PATH` and any checkout-specific `PYTHONPATH` unset so the SDK uses its bundled Worker.

   ```sh
   python -m pip install "coremind-ai==2.1.0"
   python -c "from importlib.metadata import version; print(version('coremind-ai'))"
   npx --no-install coremind --version
   npx --no-install coremind create . --runtime-only --provider deepseek --model deepseek-flash
   npx --no-install coremind doctor coremind.yaml
   ```

   Both version checks should show `2.1.0`. The `--runtime-only` flag preserves an existing configuration. Set the credential for your chosen model, run `npx --no-install coremind run coremind.yaml --prompt "Reply only OK"`, and check for a reply with zero business tool calls. Use `doctor` for the offline check.

In the 2.1.0 CLI, `providers` and `create` list configurable entries and link to the online matrix. The 2.0.0 CLI displays historical certification labels. Check the target model against the version, commit and Runtime digest in the [certification matrix](../providers/README.en.md).

## Switch one capability at a time

| Capability | Installation and first check |
| --- | --- |
| Knowledge | Install `coremind-knowledge-mcp==0.1.0` from PyPI in a separate Python 3.12 environment. Start the service with your sources, catalog, model and index location. Query as a reader and resolve a citation. Keep the withdrawal ledger when rebuilding the index. [Setup and rollback](../modules/manage-knowledge/GUIDE.en.md) |
| Hindsight memory | Install `coremind-memory-mcp==0.1.0` from PyPI in a separate Python 3.12 environment. Connect your Hindsight service, PostgreSQL and host identities. Retain, correct and forget a confirmed preference with the management identity. Check each change as a reader in a new session. [Setup and rollback](../modules/manage-memory/GUIDE.en.md) |
| Skill | Define a method in `skills/<id>/SKILL.md` and select the ID for the agent. To share it across projects, install a reviewed commit with `coremind-skill-install` from `coremind-templates@2.1.0`. Check loading, upgrade and removal in a new Runtime. [Installation and rollback](../modules/package-agent-skills/GUIDE.en.md) |
| Tools | Register a versioned business implementation with the SDK or bind an MCP operation. Grant the agent access. Check input, permission and the business receipt, then replace the implementation and repeat. Check removal in a new Runtime. [Single-tool example](../../examples/modules/build-tools/README.en.md) |
| Ontology | Install `coremind-ontology-mcp==0.1.0` from PyPI in a separate Python 3.10+ environment. Supply the project model directory and a read token. Validate one conforming and one violating record. To execute actions, supply separate write credentials, a handler and a durable receipt store. [Setup and rollback](../modules/manage-ontology/GUIDE.en.md) |

Change one component at a time. Test the Runtime baseline, a single capability and its removal, then repeat with the combinations your application uses. The four client entry points in the 49 external consumer checks used a deterministic model fixture. The 2.1.0 DeepSeek qualification is tied to its frozen commit and Runtime digest. Recheck using the identities, data and model intended for deployment. [Five-domain construction and acceptance](../en/guide/06-capability-construction.md) · [Independent component delivery](https://github.com/Eclipseic1848/CoreMind/pull/424)

## Roll back

Stop new writes to the service being replaced. Remove its Skill selection, tool registration or MCP binding and verify the remaining capabilities in a new Runtime. Retain original documents, Hindsight memory and forget records, ontology models, business receipts and pinned Skill revisions. Reconcile any action whose outcome is unknown with the business system. To roll back the clients, restore the original lockfile, 2.0.0 CLI/SDKs and matching Worker, then repeat the baseline and the checks for enabled capabilities.
