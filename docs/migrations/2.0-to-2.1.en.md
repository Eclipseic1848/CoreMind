# Try the CoreMind 2.1.0 candidate from 2.0.0

[简体中文](2.0-to-2.1.zh-CN.md)

The public stable release is `2.0.0`. To try `2.1.0`, install a candidate CLI, SDK and Worker built from the same commit in a separate application directory. Knowledge, memory and ontology are three independently installed Python services, each initially versioned `0.1.0`. A Runtime-only project needs none of these services. [Public 2.0.0 release](https://github.com/Eclipseic1848/CoreMind/releases/tag/v2.0.0) · [2.1.0 changes](../release/notes/v2.1.0.md)

## Install the candidate clients

1. Keep the existing project lockfile, configuration, run state and business data. Extract artifacts from a single candidate build into a fresh directory and check their version, commit and SHA-256 against the supplied manifest. The 2.1.0 release inventory calls for 13 artifacts: eight npm tarballs, one SDK wheel, three optional service wheels and one source ZIP. The commands assume `candidate/npm/` contains only the eight npm tarballs for this build and `candidate/python/` contains the SDK wheel. The three service wheels from engineering CI can also be evaluated separately. [Component build and artifacts](https://github.com/Eclipseic1848/CoreMind/actions/runs/45581690035)
2. Create an empty npm project and install all local tarballs together so transitive CoreMind dependencies resolve to the same version. Use Node.js 22.19 or later.

   ```sh
   npm init -y
   # Bash
   npm install --save-exact ./candidate/npm/*.tgz
   ```

   In PowerShell use `npm install --save-exact @((Get-ChildItem -LiteralPath ./candidate/npm -Filter *.tgz).FullName)`.

3. For the Python SDK, install the candidate wheel in a fresh Python 3.10+ environment. Leave `COREMIND_WORKER_PATH` and any checkout-specific `PYTHONPATH` unset so the SDK uses its bundled Worker.

   ```sh
   python -m pip install ./candidate/python/coremind_ai-2.1.0-py3-none-any.whl
   python -c "from importlib.metadata import version; print(version('coremind-ai'))"
   npx --no-install coremind --version
   npx --no-install coremind create . --runtime-only --provider deepseek --model deepseek-flash
   npx --no-install coremind doctor coremind.yaml
   ```

   Both version checks should show `2.1.0`. If a configuration already exists, `--runtime-only` preserves it. Set the credential for the model you want to use. Run `npx --no-install coremind run coremind.yaml --prompt "Reply only OK"` and check for a reply with zero business tool calls. Use `doctor` for the offline check.

In the 2.1.0 candidate CLI, `providers` and `create` list configurable entries and link to the online matrix. The 2.0.0 CLI displays historical certification labels. Check the target model against the version, commit and Runtime digest in the [certification matrix](../providers/README.en.md).

## Switch one capability at a time

| Capability | Installation and first check |
| --- | --- |
| Knowledge | Install the local `coremind_knowledge_mcp-0.1.0-py3-none-any.whl` in a separate Python 3.12 environment. Start the service with your sources, catalog, model and index location. Query as a reader and resolve a citation. Keep the withdrawal ledger when rebuilding the index. [Setup and rollback](../modules/manage-knowledge/GUIDE.en.md) |
| Hindsight memory | Install the local `coremind_memory_mcp-0.1.0-py3-none-any.whl` in a separate Python 3.12 environment. Connect your Hindsight service, PostgreSQL and host identities. Retain, correct and forget a confirmed preference with the management identity. Check each change as a reader in a new session. [Setup and rollback](../modules/manage-memory/GUIDE.en.md) |
| Skill | Define a method in `skills/<id>/SKILL.md` and select the ID for the agent. To share it across projects, install a reviewed commit with `coremind-skill-install` from the candidate `coremind-templates` package. Check loading, upgrade and removal in a new Runtime. [Installation and rollback](../modules/package-agent-skills/GUIDE.en.md) |
| Tools | Register a versioned business implementation with the SDK or bind an MCP operation. Grant the agent access. Check input, permission and the business receipt, then replace the implementation and repeat. Check removal in a new Runtime. [Single-tool example](../../examples/modules/build-tools/README.en.md) |
| Ontology | Install the local `coremind_ontology_mcp-0.1.0-py3-none-any.whl` in a separate Python 3.10+ environment. Supply the project model directory and a read token. Validate one conforming and one violating record. To execute actions, supply separate write credentials, a handler and a durable receipt store. [Setup and rollback](../modules/manage-ontology/GUIDE.en.md) |

Change one component at a time. Test the Runtime baseline, a single capability and its removal, then repeat with the combinations your application uses. The four client entry points in the 49 external consumer checks used a deterministic model fixture. The live Provider certification for 2.0.0 covers its frozen commit and Runtime digest. Recheck using the identities, data and model intended for deployment. [Five-domain construction and acceptance](../en/guide/06-capability-construction.md) · [Independent component delivery](https://github.com/Eclipseic1848/CoreMind/pull/424)

## Roll back

Stop new writes to the service being replaced. Remove its Skill selection, tool registration or MCP binding and verify the remaining capabilities in a new Runtime. Retain original documents, Hindsight memory and forget records, ontology models, business receipts and pinned Skill revisions. Reconcile any action whose outcome is unknown with the business system. To roll back the clients, restore the original lockfile, 2.0.0 CLI/SDKs and matching Worker, then repeat the baseline and the checks for enabled capabilities.
