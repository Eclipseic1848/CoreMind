# 从 1.0 升级到 1.2

[English](1.0-to-1.2.en.md)

本页记录 1.2 开发线的迁移边界，不表示版本已经发布。由 1.0 升级时也应阅读[从 1.0 升级到 1.1](1.0-to-1.1.zh-CN.md)中的既有迁移要求；全部 CoreMind npm 包、Python SDK 与随包 Worker 应使用同一发布版本。本节说明 1.2 新增的项目脚本加载信任。

## 项目脚本加载信任

配置的脚本工具会在 Runtime 初始化时 import，模块顶层与传递依赖具有宿主进程权限。因此存在实际脚本入口时，加载前必须由宿主明确同意；未提供决定、拒绝或回调抛错均以 `execution_security_violation` 拒绝，取消保持 `aborted`。没有项目脚本的配置不需要此决定。缺失脚本仍可由原加载器告警跳过；未经本批批准、之后出现的入口不能加载。

TypeScript 宿主使用唯一的 `approveProjectCode(request, signal)` 回调。请求列出规范项目目录、去重排序的入口路径、入口 SHA-256 与整批 fingerprint。批准范围包含所有实际构建 Agent 的有效全局继承、独立和 deferred 工具；每次真实 import 前再次确认入口。仅对自己已审查的代码返回 `true`：

```ts
const runtime = await CoreMindRuntime.create({
  config,
  configDir,
  approveProjectCode: async (request) => approvedFingerprints.has(request.fingerprint),
});
```

CLI 的 `run`、`chat`、`eval` 共用这项决定。TTY 默认询问，空回答、拒绝、EOF 和取消都不批准；提示只写 stderr。同一命令进程以完整 fingerprint 复用决定，不保存永久许可。非 TTY 不读取管道内容作为同意；只有显式 `--trust-project-code` 或 `--trust-project-code=true` 才允许可信项目脚本，`false` 明确拒绝，其他值报错。工具的 `--permission full` 不表示信任脚本。`doctor` 和 `check` 保持静态，不 import 项目脚本。

Python 同步和异步客户端增加关键字参数 `trust_project_code: bool = False`；严格只接受 bool。只有已审核项目才显式传 `True`。标准 Worker 的 v1/v2 initialize 新增 `trustProjectCode` boolean，并报告 `projectCodeTrust` 能力。新 SDK 在发 run/chat 或注册 callable 前要求该能力，即使默认 `False` 也不能降级到旧 Worker。旧 Worker 需与 SDK 一起升级；v2 schema fingerprint 和默认 Worker 来自同次构建。v1 工具发现挑战的一次重发保留原信任字段。

加载同意不允许工具调用、文件访问、联网、凭据或 Child 权限。工具审批、deny、工作区与恢复安全门继续生效。入口摘要不证明全部传递依赖不可变，也不能防止拥有宿主权限的外部进程在检查后替换文件；本机制不是 OS 沙箱。宿主已加载的生命周期扩展或函数对象不重复询问。直接调用低层 `loadScriptTool()` / `buildTools()` 表示调用者已信任指定来源，不能用于绕过配置驱动 Runtime 的加载决定。
