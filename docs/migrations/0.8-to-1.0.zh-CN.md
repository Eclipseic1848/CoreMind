# 从 0.8 升级到 1.0

[English](0.8-to-1.0.en.md)

1. 停止 CLI、Worker 与 SDK 进程；备份 `.coremind/`、Session、Checkpoint 和外部副作用收据。
2. 将全部使用的 CoreMind npm 包与 Python SDK 同步到 `1.0.1`。Node.js 要求 >=22.19，Python >=3.10，Git 工具要求 Git >=2.36。公开可用性以 Release、npm 和 PyPI 为准。
3. 使用匹配 SDK 的 bundled Worker；不要混用严格 Schema 指纹不一致的版本。新程序可读旧日志；旧程序不能继续写入含 admission 的新日志。回滚使用升级前备份及对应旧版本。
4. Config v2 和 Protocol v1/v2 保持支持。v1 Python 工具仅在 Worker 声明 `scopedToolResults` 时回传 `runId`，`callId` 不改变。取消停止本地等待，不保证外部函数已停止；未确认收尾时 `quiescent` 为 false。
5. 复验写工具审批、网络策略和 Windows Shell 三条件。Linux Web 使用独立宿主网络域，不能继承 Shell 断网沙箱的隔离声明。
6. Trace 对可识别凭据失败关闭或脱敏。含凭据的步骤候选返回 `redaction_failed`；无空白流式片段可能延迟到轮次结束，未闭合片段超过 65,536 字符会失败。普通候选原文和哈希保持不变。
7. 检查 token/费用耗尽、摘要取消、暂停恢复、Python 迟到结果和 `/abort`；`/exit` 仍等待本轮完成，`--print` stdout 仅正文。
8. 从 `1.0.0` 升级到 `1.0.1` 时，Protocol v2 的 `tool_register.parameters` 会完整保留 JSON Schema 字段。升级 SDK 时同步升级 bundled Worker，不混用旧 Schema 指纹；若需回滚，停止进程后将 SDK 与 Worker 一起退回 `1.0.0`，并使用升级前备份恢复需要回滚的持久状态。

完整变化见[变更日志](../../CHANGELOG.md)。本版本的真实 Provider、双平台 PTY 与公开制品证据须独立核对，不能复用旧发布豁免。
