# 从 1.0 升级到 1.1

[English](1.0-to-1.1.en.md)

本页保留未独立发布的 1.1.0 历史草稿，能力并入 1.2.0 目标。请直接使用[1.0.1→1.2.0 候选迁移指南](1.0-to-1.2.zh-CN.md)，无须先安装 1.1。以下旧正文仅供历史追溯，不作为新接口或最终发布资格的依据。

1. 升级前停止 CLI、Worker 与 SDK，备份 `.coremind/`、Session、Checkpoint 和外部副作用收据。全部 CoreMind npm 包、Python SDK 与内置 Worker 应使用同一发布版本。
2. 现有 Config v2、Protocol v1/v2 与 V4 会话格式保持支持。会话存储、分支、顺序、摘要和操作收据采用兼容实现；不要求重写用户日志。系统提示与工具声明仅在请求边界装配，不新增到既有会话正文。
3. 历史压缩摘要继续转换为模型可读正文。回放请求使用同一转换，原始会话条目不变。升级验收应覆盖恢复、分支、摘要和继续追加，不能仅检查新建会话。
4. Azure 内置配置继续接受 `azure-openai-responses`，实际模型路由使用 `azure`。显式环境变量与凭据引用仍是唯一来源，不回退到宿主凭据。同名自定义 `baseUrl` 不受别名转换影响。分类专用目录不作为聊天入口列出；目录存在不等于真实 Provider 已认证。
5. Linux Shell 保留严格断网、文件保护和凭据限制。私有后端与本机架构 helper 随 npm/Python 产物一起发布；缺失、摘要错误或系统隔离能力不足时拒绝执行。不要单独复制 Worker 而遗漏同目录 `vendor/linux-sandbox`。开发构建源中的证书及代理模块不进入运行闭包。
6. 回滚时停止进程，将全部 SDK 与 Worker 一起退回 `1.0.1`，恢复升级前备份。不要让新旧进程同时写同一会话，也不要移动或覆盖已发布的版本。

Protocol v2 的终态查询、包含当前终态的事件页及过期游标中的终态投影，在返回前等待该 Run 的宿主收尾。单一调用方收到终态后，可以在同一 Worker 启动下一 Run；真正执行中的并发请求仍返回 `worker_busy`。历史暂停、恢复前的旧快照和不含当前终态的早期事件页不会等待当前执行结束。该屏障不代表 Child 业务均已处置，也不排除其他调用方并发占用 Worker。

Linux helper 由宿主进程持有，多次命令和多个 Runtime 共用一个私有目录；即使宿主临时目录位于工作区内，沙箱命令也不得修改此执行资产。单次 Run 结束不释放仍在使用的进程资源。正常进程退出会同步清理，显式后端关闭可重试清理失败。Python 正常关闭先发送 EOF 等待 Worker 退出；超时后的信号终止、强杀或系统崩溃不保证执行退出清理。嵌入 SDK 不接管宿主信号。

标准技能仍使用 `agents.<name>.skills` 选择目录 ID。内置技能及仅含 README.md 的项目技能继续全文进入稳定前缀；配置目录 `configDir/skills/<id>/SKILL.md` 的首请求只放索引，正文经 ToolPolicy 下的 `load_skill({"id":"<id>"})` 按需加载。同 ID 内置优先；同目录双文件选 SKILL 并告警，损坏不回落。单个项目源文件上限 256 KiB，解析结果与全部 Agent 冻结快照各上限 2 MiB 序列化 UTF-8 JSON；正文和快照 SHA 均为无前缀的 64 字符十六进制值。

标准技能在 Runtime 创建后冻结，Child 与恢复使用原身份；文件修改需新 Runtime 才生效。已有标准技能 Run 从原 start 快照恢复，不用当前文件替换缺失或损坏快照，原配置及恢复门仍生效。原始受信 Store 含冻结正文，公开投影、事件和遥测剥离技能私有旁挂字段；这不等于会话或业务输出没有正文，也不防持有 Store 的宿主重新计算 SHA 后改写。关闭 Session 不承诺恢复完整对话。技能不增加工具权限，也不提供远程发现或脚本执行；格式和重载规则见[技能指南](../guide/03-skills.md)。

运行中输入控制复用现有协议与收件箱。TypeScript 使用 `ChatSession.steer/followUp(message, options?)`，可保留 `{ controlId, runId }` 固定重试和预期目标；实际投递绑定调用时的活动 Turn Runtime，未就绪、未绑定、已封口或错误 Run 均拒绝，不误投下一轮。CLI 两入口使用 `/steer 文本`、`/follow-up 文本`；普通忙时文字仅保留一份草稿，空闲后确认，不自动执行或覆盖旧稿。审批命令不代替批准；迟到控制回执不清除后来草稿。

`accepted/applied/rejected/duplicate/conflict` 与 `input_*` 输入事件独立；applied 不代表消费或完成。冷恢复继续 accepted 控制，applied 未确认消费者不重投，只明确 discarded；暂停原输入仍按原门恢复，普通原输入已 discarded 时仍拒绝恢复。提交与内存交付的崩溃窗口仍存在，不承诺绝对 exactly-once。Python sync/async 继续使用既有 v2 `control/events/query`、显式 `after_sequence` 和默认随包 Worker，无新 API 或协议版本；首次输入、Session 与完整对话重建仍遵守原合同。

本版本的双平台、真实 Provider 和公开安装证据必须重新取得；1.0.1 的发布证据不能替代新版本验收。
