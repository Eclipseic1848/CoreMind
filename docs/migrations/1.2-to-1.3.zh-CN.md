# 从 1.2 升级到 1.3

[English](1.2-to-1.3.en.md)

> 本指南对应 `1.3.0` 发布准备。只有同版本 Release、npm/PyPI 制品和最终资格证据确认后，才按正式版本切换；源码或工程 CI 通过不表示已经公开发布。完整变更见[双语发布说明](../release/notes/v1.3.0.md)。

## 升级前

停止正在使用旧版本的 CLI、SDK 和 Worker，备份配置、Session、RunState、Checkpoint 与业务文件。全部 CoreMind npm 包、Python SDK、bundled Worker 同步更新为 1.3.0，避免新旧进程并发写入同一状态目录。保留 Node.js ≥ 22.19、Python ≥ 3.10 和 Git 工具的 Git ≥ 2.36 要求。

Config/Protocol 版本不升级；Config v2/v3、Protocol v1/v2 的原边界与 v2 Schema 指纹校验继续保留。`ToolPolicy` 构造选项新增可选 `protectedPaths` 保护条目，`authorize()` 的 `identity` 新增可选 `signal?: AbortSignal`，既有调用保持兼容。SDK 和 Worker 仍须匹配，不能因某项修复未改 wire shape 就混用不同版本。1.2 以前版本先按[1.0→1.2 指南](1.0-to-1.2.zh-CN.md)核对既有迁移要求。

## 检查行为变化

### 文件与框架状态

普通业务工具不能写框架管理的持久状态，三档权限和显式 allow 都不能覆盖该保护。把业务输出放在合法业务路径；恢复、清理和状态维护仍交给宿主维护接口。现存文件有多个硬链接时，普通工具写入会拒绝，读取仍按原权限；需要修改时由宿主明确处理链接关系。保留合法工作区文件的审批与 Checkpoint 流程；此保护不隔离任意宿主代码。

### Workflow 输出与取消

同一 Agent 连续运行时，模型仍可使用同一 Session 历史；`prompt`/`call` 的步骤输出、`saveAs`、后续插值和 transcript 只取本步骤新增 assistant 文本。例如前两步分别产生 A、B，第二步结果应为 B。若业务解析依赖历史回答被重复拼入结果，需调整解析与断言。

`parallel` 首次失败或暂停会取消同组其他步骤并等待收尾，保留首个错误；Run 结束后不再准入新模型调用。全成功仍按声明顺序聚合。取消不撤销已经开始的工具操作，继续按收据核对副作用。

### Python v1 工具 Schema

`@client.tool` 自动 Schema 解析 `from __future__ import annotations` 及字符串形式的 `int`、`str`、`bool` 和已有容器注解。无法解析的前向引用须提供显式 `parameters`；原显式 Schema 保持兼容，复杂 typing 不超出既有支持范围。

Node 侧仍先按既有规则转换再校验，例如 `int` 参数的字符串 `'5'` 可转为整数 `5`；转换后仍未通过 Schema 的参数才在 callable 执行前拒绝。不要将修复理解为严格拒绝所有原始类型差异。

### Diff grader

`preserveExisting: false` 仅关闭旧脏内容保护，不能绕过 `allowedPaths`、`forbiddenPaths`、`requiredPaths` 或 `maxChangedFiles`。变化集包含基线与终态的状态或内容变化；状态和内容均未变化的既有脏文件不计，原 untracked 文件删除计入变化。原 stage/unstage 计数和默认 `true` 保护保持。检查原评测是否依赖被遗漏的变化，按业务允许范围修正用例，而不是移除约束。

### Protocol v2 启动失败

已接受 Run 的 Runtime 初始化失败会保留共享分类的稳定错误码、对应终态与安全消息，可用 `query`/`events` 查询。消费端应按实际错误合同处理，不再假定全部是 `agent_failed`。未知 `unclassified_error` 保守暂停且要求人工审计；暂停并不自动证明可安全 `resume`。本轮不增加错误字段，也不公开凭据或原始堆栈。

### Web 工具收尾

`web-fetch`/`web-search` 的非 2xx 或正文读取失败会先等待正文取消/释放的清理尝试结束，再结算本地网络活动；清理失败不覆盖原 HTTP/读取错误。保留正常结果、取消、权限与网络策略，`web-fetch` 的 2 MiB 上限不变；不向 `web-search` 增加新的大小合同。

### readline 与 doctor

readline `/exit`、`!exit` 现在先请求取消活动 Run 并等待收尾，与 TUI 一致。若管道希望等待已开始的普通回答自然完成，应使用原 EOF 路径；空闲、审批和 MCP 登录等待的既有行为保持。退出不会自动回滚已开始工具副作用。

`doctor <配置文件>` 复用所选 Provider 的既有凭据策略，合法匿名/Header-only 自定义端点不要求无关 API key；带 `baseUrl` 的内置同名入口也按自定义端点处理。显式缺失凭据仍失败，原生内置鉴权要求不变。无配置时保留通用体检；诊断不加载项目脚本、不发 Provider 请求，不证明凭据有效或真实连通。

安全策略的支持表和已交付能力说明已校正；支持政策、`0.3.1` 重大安全问题例外和私密披露方式没有扩大，见[安全策略](../../SECURITY.md)。

## 验证与回滚

先在备份副本验证业务文件写入与状态保护、同 Agent 输出、并行失败/暂停收尾、Python 自动/显式 Schema、Diff 变化集、v2 错误持久查询、Web 失败清理、显式退出与 EOF，以及 doctor 凭据策略。使用框架已有测试与业务评测，不把一次成功当成完整发布资格。

正式发布须使用绑定 1.3.0 最终 main、Runtime/Worker 与准确制品的严格 Provider、双平台工程/稳定性/覆盖率/真实 PTY 和公开回装证据。旧版本认证不可复用；本地受控夹具不认证外部 Provider/OAuth/MCP 互通。

需要回滚时停止新进程，将程序、SDK 与 Worker 一起恢复到已发布 1.2.0，并恢复升级前配置和持久状态备份。不要让旧程序继续写入无法理解的新事实，也不要并发启动两版本写同一状态。人工核对外部效果后再决定补偿或重试；恢复本地文件不撤销外部操作，已发布同版本制品不得覆盖。
