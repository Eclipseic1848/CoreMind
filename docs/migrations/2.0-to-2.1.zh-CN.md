# 从 CoreMind 2.0.0 试用 2.1.0 候选

[English](2.0-to-2.1.en.md)

公开稳定版为 `2.0.0`。要试用 `2.1.0`，在独立业务目录中安装同一提交构建的候选 CLI、SDK 和 Worker。知识、记忆和本体是三个单独安装的 Python 服务，初版均为 `0.1.0`。只运行 Runtime 的项目无需安装任何服务。[2.0.0 公开发布](https://github.com/Eclipseic1848/CoreMind/releases/tag/v2.0.0) · [2.1.0 变更说明](../release/notes/v2.1.0.md)

## 安装候选客户端

1. 保留现有项目的包锁、配置、运行状态和业务数据。在新目录解压同一候选构建的安装件，并按随包清单核对版本、提交和文件 SHA-256。2.1.0 正式交付清单共 13 件，即 8 个 npm tarball、1 个 SDK wheel、3 个可选服务 wheel 和 1 个源码 ZIP。以下命令假设解压后的 `candidate/npm/` 仅包含该构建的八个 npm tarball，`candidate/python/` 包含 SDK wheel。已有工程 CI 的三份服务 wheel 可以单独试用。[组件构建与附件](https://github.com/Eclipseic1848/CoreMind/actions/runs/45581690035)
2. 创建空的 npm 项目，安装全部本地 tarball，防止传递依赖从公共仓库选到另一版。Node.js 需要 22.19 或更新版本。

   ```sh
   npm init -y
   # Bash
   npm install --save-exact ./candidate/npm/*.tgz
   ```

   PowerShell 中使用 `npm install --save-exact @((Get-ChildItem -LiteralPath ./candidate/npm -Filter *.tgz).FullName)`。

3. 需要 Python SDK 时，在新的 Python 3.10 及以上虚拟环境中安装候选 wheel。不设置 `COREMIND_WORKER_PATH` 或仓库的 `PYTHONPATH`，直接验证 wheel 自带的 Worker。

   ```sh
   python -m pip install ./candidate/python/coremind_ai-2.1.0-py3-none-any.whl
   python -c "from importlib.metadata import version; print(version('coremind-ai'))"
   npx --no-install coremind --version
   npx --no-install coremind create . --runtime-only --provider deepseek --model deepseek-flash
   npx --no-install coremind doctor coremind.yaml
   ```

   两个版本检查均应显示 `2.1.0`。配置已存在时，`--runtime-only` 保留原文件。为实际使用的模型设置凭据，执行 `npx --no-install coremind run coremind.yaml --prompt "只回答 OK"`，确认回复且业务工具调用数为零。`doctor` 单独用于离线检查。

2.1.0 候选 CLI 的 `providers` 和 `create` 显示可配置入口，并提供在线矩阵地址。2.0.0 CLI 会显示历史认证标签。核对目标模型时按实际版本、提交和 Runtime 包摘要查看[认证矩阵](../providers/README.zh-CN.md)。

## 按需切换一项能力

| 能力 | 安装与最小验收 |
| --- | --- |
| 知识 | 在独立 Python 3.12 环境安装本地 `coremind_knowledge_mcp-0.1.0-py3-none-any.whl`。用业务方的原文、目录、模型和索引位置启服务，按读者身份查一条结果并解析引文。保留撤回清单再重建索引。[接入与回退](../modules/manage-knowledge/GUIDE.zh-CN.md) |
| Hindsight 记忆 | 在独立 Python 3.12 环境安装本地 `coremind_memory_mcp-0.1.0-py3-none-any.whl`，绑定既有 Hindsight 服务、PostgreSQL 和宿主身份。用管理身份写入已确认偏好、更正或遗忘，每次用只读身份在新会话核对结果。[接入与回退](../modules/manage-memory/GUIDE.zh-CN.md) |
| Skill | 在业务项目 `skills/<id>/SKILL.md` 定义方法，由 Agent 选择 ID。需要跨项目复用时，用候选 `coremind-templates` 的 `coremind-skill-install` 安装审核过的固定提交。用新 Runtime 检查加载、升级及移除。[安装和回退](../modules/package-agent-skills/GUIDE.zh-CN.md) |
| 工具 | 用 SDK 注册带版本的业务实现，或经 MCP 绑定一项操作，为 Agent 授权。核对输入、权限和业务回执，更换实现后重测。移除注册后启动新 Runtime 验证。[单工具示例](../../examples/modules/build-tools/README.zh-CN.md) |
| 本体 | 在独立 Python 3.10 及以上环境安装本地 `coremind_ontology_mcp-0.1.0-py3-none-any.whl`。提供业务方的模型目录和只读令牌，分别校验一个合规和一个违规样本。需要执行动作时，另配写入凭据、处理器和持久回执库。[接入与回退](../modules/manage-ontology/GUIDE.zh-CN.md) |

一次只变更一个组件。先验证空白 Runtime、单项启用和移除，再用实际需要的组合复跑。四个客户端入口和 49 项仓库外检查的模型侧使用确定性夹具。2.0.0 的真实 Provider 认证仅覆盖其冻结提交及 Runtime 摘要。业务部署应在目标身份、数据和模型上复验。[五域建设与验收](../guide/06-capability-construction.md) · [五域独立交付](https://github.com/Eclipseic1848/CoreMind/pull/424)

## 回退

先停止待替换服务的新写入。项目可以撤销一个 Skill、工具注册或 MCP 绑定，并在新 Runtime 中验证其余能力可用。保留业务原文、Hindsight 记忆与遗忘记录、本体模型、业务回执和 Skill 固定版本记录。对结果未知的动作先核对业务系统。客户端需回退时恢复原包锁、2.0.0 CLI/SDK 及其配套 Worker，随后复跑基线和仍启用的能力。
