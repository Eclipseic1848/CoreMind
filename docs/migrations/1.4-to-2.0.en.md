# Upgrade CoreMind from 1.4 to 2.0

[简体中文](1.4-to-2.0.zh-CN.md)

Upgrade the CLI, SDKs and Worker together in an isolated project. Add business assets as needed. Existing sessions and durable tasks retain their identities, permissions and fact records. When enabling Hindsight, the host chooses which confirmed facts enter each bank.

## Upgrade the software

1. Save package locks, configuration and Worker versions. Back up Session, Run, Workspace and durable-task records. Pause writers and create a separate copy for the rehearsal.
2. Install the matching CLI, SDK and wheel from npm and PyPI. Their digests were verified against the release manifest. [Public reinstall](https://github.com/Eclipseic1848/CoreMind/issues/404#issuecomment-7154981484) Node.js 22.19 or later and Python 3.10 or later are required for the SDKs. Use each optional service's documented Python version and dependencies.

```sh
npm install --save-exact coremind-ai@2.0.0 coremind-cli@2.0.0
python -m pip install coremind-ai==2.0.0
npx coremind --version
python -c "import coremind; print(coremind.__version__)"
```

3. Use the matching wheel's bundled Node Worker. If your host sets `COREMIND_WORKER_PATH`, upgrade and verify that Worker too. Existing v1 clients continue to work. Explicit Protocol v2 access retains schema fingerprint and capability negotiation.

## Connect your business assets

| Asset | Upgrade and check |
| --- | --- |
| Knowledge | Keep originals, stable document IDs, versions and reader scopes. Rebuild and ask one answerable and one unanswerable question. Check the file, version and location. For Markdown tables, verify that search and citation lookup return the data row and the header row from the same version. Withdraw a version, repeat the query, and resolve an old citation as an unauthorized reader. |
| Memory | Assign a Hindsight bank to the person or project. Separate reader and administrator tokens. Confirm a preference, recall it in a fresh session, correct it, forget it and check a second reader. Preserve current receipts and replay forgetting before exposing a restored database. |
| Skills | Existing Skills remain usable. Declare new references, assets or scripts and pin their versions. Reinstall into a fresh project, compare digests and resume an older Run with its frozen snapshot. Review generated drafts before sharing them. |
| Tools | Keep host approval and original request IDs. Verify empty values, cancellation, disconnects and unknown outcomes on the required local, stdio or HTTP paths. Pin Playwright MCP and check browser cleanup before enabling it. |
| Ontology | Projects needing action semantics supply local Turtle models, SHACL shapes and mappings. Inspect conforming and violating examples with a read token. Configure write authority, preconditions and actual receipts separately. Ordinary document projects use the default configuration. |

Run the ordinary and ontology-enabled variants from the template. Verify citations, preferences, permissions and written files across separate identities, projects and sessions. Each module supplies implementation, SOP, Skill and examples. ## Rollback

Stop 2.0 writers and preserve diagnostics and external action receipts. Restore the 1.4.0 CLI, SDKs, Worker, configuration and pre-upgrade state together. Retain document sources, version catalogs and the latest forgetting receipts, including deletions made since the upgrade. Have the host reconcile any unknown action before deciding whether to submit it again.
