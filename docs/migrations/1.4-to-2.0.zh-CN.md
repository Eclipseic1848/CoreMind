# 从 CoreMind 1.4 升级至 2.0

[English](1.4-to-2.0.en.md)

先在独立项目中升级 CLI、SDK 与 Worker，再按需接入业务资产。现有会话与持久任务继续使用原来的身份、权限和事实记录。启用 Hindsight 时，由宿主选择哪些已确认事实进入哪个记忆库。

## 升级软件

1. 保存现有包锁、配置和 Worker 版本。备份 Session、Run、Workspace 与任务状态。暂时停止写入，再为演练建立独立副本。
2. 候选阶段从同一候选清单安装 npm tarball 和 Python wheel。公开渠道提供对应摘要后，可用下列命令升级。使用 Node.js 22.19 或更高版本；Python SDK 需要 Python 3.10 或更高版本。可选 Python 服务请使用各模块公布的版本与依赖。

```sh
npm install --save-exact coremind-ai@2.0.0 coremind-cli@2.0.0
python -m pip install coremind-ai==2.0.0
npx coremind --version
python -c "import coremind; print(coremind.__version__)"
```

3. Python 优先使用同版本 wheel 所带的 Node Worker。若宿主设置了 `COREMIND_WORKER_PATH`，同步升级并检查其身份。已有 v1 客户端可继续使用；显式使用 Protocol v2 的入口继续核对 Schema 指纹及协商能力。

## 接入五类资产

| 能力 | 迁移与复验 |
| --- | --- |
| 知识 | 保留原始文件、稳定文档标识、版本与阅读范围。重建索引后查询一个有答案及一个无答案的问题，核对文件、版本和位置。若项目使用 Markdown 表格，分别从检索和引文解析结果核对数据行及同一版本的表头行。撤回后，从同一身份查询，再换无权限身份解析旧引文。 |
| 记忆 | 为个人或项目分配 Hindsight bank，分开读令牌和管理令牌。确认偏好后在新会话召回，再更正、遗忘并检查对照主体。恢复数据库时保留最新回执，重放遗忘后再开放访问。 |
| Skill | 旧 Skill 可继续使用。为新增 references、assets 或 scripts 声明资源并固定版本。在新项目重装后复核摘要；对旧 Run 测试按原快照恢复。生成的草稿由业务方复核后发布。 |
| 工具 | 保留宿主审批和原有请求 ID。验证本地、stdio 或 HTTP 路径对空值、取消、断连和结果未知的处理。启用浏览器前固定 Playwright MCP 版本并验证退出与清理。 |
| 本体 | 需要动作语义的项目提供本地 Turtle 模型、SHACL 形状和映射。先用只读凭据检查合规与违规实例，再独立配置写权限、前置条件和真实结果回执。普通资料项目使用默认配置。 |

从模板运行普通版与可选本体版，用独立主体、项目和会话核对资料引用、偏好、权限及输出文件。模块提供实现、开发 SOP、Skill 与样例。[五域建设指南](../guide/06-capability-construction.md) · [模板用法](../../packages/coremind-templates/templates/general/document-assistant/README.md) · [已知限制](../release/KNOWN-LIMITATIONS.zh-CN.md)

## 回滚

停止 2.0 的 writer，保留现场和实际发生的外部动作回执。将 CLI、SDK、Worker、配置及原有持久状态一起恢复到升级前的 1.4.0 副本。保留业务原文、版本清单和最新遗忘记录，尤其是升级后产生的删除。将结果未知的业务动作交由宿主对账后再决定是否重新提交。
