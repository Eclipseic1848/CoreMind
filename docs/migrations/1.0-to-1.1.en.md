# Upgrade from 1.0 to 1.1

[简体中文](1.0-to-1.1.zh-CN.md)

This page records migration boundaries during 1.1.0 development. It does not announce a release. Check the Release, npm, and PyPI for availability.

1. Stop CLI, Worker, and SDK processes. Back up `.coremind/`, Sessions, Checkpoints, and external side-effect receipts. Keep all CoreMind npm packages, the Python SDK, and its bundled Worker on the same release.
2. Config v2, Protocol v1/v2, and V4 sessions remain supported. Compatible storage preserves branches, ordering, summaries, and operation receipts without rewriting user logs. System instructions and tool declarations are assembled at the request boundary rather than added to existing session bodies.
3. Historical compaction summaries remain model-readable. Request replay uses the same conversion without changing original session entries. Verify recovery, branching, compaction, and subsequent appends as well as new sessions.
4. Built-in Azure configuration still accepts `azure-openai-responses`, with `azure` as the actual model route. Explicit environment variables and secret references remain the only credential source. Custom `baseUrl` providers with the same name are unchanged. Classification-only catalogs are excluded from chat entries; catalog support is not live provider certification.
5. Linux Shell retains network denial, file protection, and credential restrictions. npm and Python artifacts include the private backend and architecture-specific helper. Missing assets, incorrect hashes, or unavailable isolation capabilities deny execution. Copy the `vendor/linux-sandbox` directory with the Worker. Certificate and proxy modules from the development build source are excluded from runtime artifacts.
6. To roll back, stop processes, restore all SDKs and the Worker to `1.0.1`, and restore the earlier backup. Never let different versions write the same session concurrently or overwrite a published version.

The host process owns one private Linux helper directory shared by commands and Runtime instances. Sandboxed commands cannot modify this executable asset even when the host temporary directory is inside the workspace. Finishing a Run does not release resources still owned by the process. Normal process exit cleans it synchronously; explicit backend shutdown can retry a cleanup failure. Python closes Worker stdin and waits for normal EOF shutdown first. Timeout termination, forced kills, and system crashes do not guarantee exit cleanup. Embedded SDKs do not install host signal handlers.

This release needs fresh platform, live provider, and public installation evidence. Evidence from 1.0.1 does not qualify a new release.
