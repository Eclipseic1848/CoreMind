# CoreMind 任务泛化验证

审查基线为 `3eb5b34`，测试种子为 `20261126`。修复前后使用相同的历史场景、生成输入和判分规则。逐例回执包含输入、预期、实际结果、耗时及通过状态。复跑环境、命令和新增任务的可运行示例见[评测与扩展指南](./README.zh-CN.md)。

## 能力与抽象

| 入口或类型 | 输入与执行机制 | 扩展成本 |
| --- | --- | --- |
| CLI、TypeScript、Python SDK | CLI 和 TypeScript 使用同一 Runtime，Python 经 stdio Worker 接入。Runtime 负责调用 Agent、工具、权限和预算，记录 Trace 和 RunOutcome。 | 增加一种业务流程通常可组合已有 Agent、工作流和工具。 |
| 持久任务 | `TaskDefinition` 提供 `type/version/initialPhase/checkpointSchema/phases`，可选 `migrate`。宿主向 `TaskSession.open` 注册，`start` 按类型校验初始检查点，`resume` 每次执行一个阶段。 | 同一宿主新增业务类型只需提供定义并注册。已存在的持久状态有版本和迁移约束。 |
| `prompt`、`call` | `agent` 加可选 `input/saveAs/retry`，交给编排器执行。 | 新节点原语涉及配置 Schema、语义校验、运行分派和测试。 |
| `parallel`、`if`、`switch` | 分别接收子步骤，条件与分支，或变量名与 case 映射。 | 可以嵌套组合现有节点。 |
| 顶层 Loop | execute、verify、repair 及可选 planning，受迭代、修复上限和验收约束。 | 文本条件与宿主的验收决定分别可测。 |
| 黄金业务与编码示例 | 订单、合同、研究、销售、修复循环、TypeScript 和 Python 缺陷分别使用项目配置和评测场景。 | 仓库没有从任意自然语言请求推断上述七种 `TaskType` 的统一分派器。这是应用级样例集。 |

持久任务原例的检查点分别是整数（counter、alarm-demo、example）和字符串（lookup）。新套件增加对象型 lookup，覆盖必填项、额外字段、值类型与长度约束；example 直接复用跨语言示例的注册定义和实际写入工具。知识、记忆、Skill、工具传输及本体作为可选组件独立验证。

主要代码见[任务注册与恢复](../../../packages/coremind-runtime/src/task-session.ts)、[工作流 Schema](../../../packages/coremind-config/src/schema/workflow.ts)、[编排器](../../../packages/coremind-runtime/src/orchestrator.ts)、[Loop](../../../packages/coremind-runtime/src/loop-runner.ts) 与 [Python Worker](../../../packages/coremind-worker/src/stdio.ts)。

## 历史任务与日志

- 原始 YAML 共 8 条，含黄金示例 6 条、编码示例 2 条。Python 销售题另按原 YAML 的输入与验收词经 SDK、Worker 和原工具实际运行，同时检查生成的 JSON。工程内核四个跨文件场景和宿主恢复等测试单列，避免把同一个 YAML 再累计一次。
- 固定知识集有依据的 30 道题中，FTS5、dense、sparse、hybrid 的首位命中分别为 27、29、30、29，前五位均为 30/30。四种检索对 10 道无依据题都返回候选。单独的 13 道留出题使用稀疏检索和冻结回答，其中 7/7 回答及引用正确，6/6 正确拒答。内存和落盘 Qdrant 的 120 次有序搜索结果一致。
- 对原有 337 份 JSONL 只读核对，共 1,273 条记录。329 份有起止时间，成功 317、失败 9、中止 3，已终结成功率 96.35%。另有 8 份缺首尾。已终结耗时合计 83.708 秒，中位数 10 毫秒。294 份 parity 全成功，34 份 provider-certification 中 23 成功、8 失败、3 中止，另有 1 份诊断失败。35 份有首轮输入与配置指纹，0 份内嵌完整配置。原始日志属于历史观察，不能据此复建当时的外部模型和工具结果。
- 原三轮资料整理仅能独立重跑检索与撤回部分。首轮前五个候选仅覆盖现行证据 2/7、旧版对照 0/3；第二轮 2/2、第三轮 1/1。撤回后回查符合预期。另一套三轮组合示例有独立验收，两个数据集各自报告。
- 首轮并发测量出现 Python Worker 初始化超时、一个故障注入子进程超时；隔离复测分别通过，子进程测试 6/6。Docling 首次使用缺依赖的解释器，切换专用解释器后 PDF、DOCX、Markdown 三项均通过。原始失败回执保留。

## 变体与判分

- 业务与编码通过生产 Runtime 或 Python SDK 执行。订单比对工具返回与最终答复；研究同时查工具命中项和引用；销售核对 CSV 的独立预期和磁盘产物；编码使用独立解释器执行修复前后的定价函数，并检查改动路径。合同和修复循环的部分样例故意注入阶段输出，用于检验传值、结果结构和控制流。
- 工作流执行生产配置校验、Orchestrator 和 LoopRunner，使用离线回显 Agent。持久任务执行公共 TaskSession，并检查两次恢复、睡眠唤醒、取消、重复 ID、稳定键重用与真实写入次数。检索变体使用新合成的版本化资料、独立事实和 BGE-M3 稀疏编码器。正式语言模型实测统一调用百炼公网快照 `deepseek-v4.1-flash-1017`。
- 输入包括边界、空值、冗余字段、错类型、约束违反、组合、多行文本，以及含运算符或模板符号的字面数据。每个变体的 `passed` 由对应任务的判分器产生。正确拒绝坏输入属于通过。固定工具次数、单独的 RunOutcome 和固定模型回复都不能独自证明业务成功。

### 公网生成与验收

固定 40 题由百炼公网快照 `deepseek-v4.1-flash-1017` 实际生成与校验。三轮使用同一题集（SHA-256 前缀 `36d0889f`）、同一检索器、温度、生成/验证预算 192/32 tokens 和原有严格评分。

| 指标 | 原版 | 原设置重复 | 修复后 |
| --- | ---: | ---: | ---: |
| 严格业务成功 | 10/40 | 10/40 | **37/40** |
| 有依据，短答与引用均被接受 | 0/30 | 0/30 | 27/30 |
| 无依据，模型主动正确拒答 | 10/10 | 10/10 | 10/10 |
| 用时 | 227.7 秒 | 228.7 秒 | 205.1 秒 |

两道探针的原验证请求把全部 32 个 token 用于思考，返回空正文；禁用该快照的思考后，两题均在 6 个 token 内返回有效 JSON。正式修复只在该供应商支持的固定快照上启用这个设置。70 次成功响应均核对了模型标识且正常结束。评分端额外输出主动达标数和验证器拦截后的达标数。[评测代码](../../knowledge-evals/zh-retrieval/answer_benchmark.py)

修复后的 Q01、Q05、Q09 引文正确，业务短答未满足原有精确匹配。例如 Q09 返回“星期四”，参考答案是“每周四”。本报告保留原分数。要建立语义等价打分，应先标注哪些措辞可以互换、哪些会改变业务含义，并测试误判率。

### 公网编码

两个原始编码场景均通过原始 grader 和安全验收。64 个生成变体首轮通过 51 个（TypeScript 23/32、Python 28/32）。一次上游瞬时错误重试通过。核对原样例权限后，评测宿主允许读取项目已跟踪源码、测试和只读 Git 差异，对原先 12 个权限拒绝项复测，11 个通过。最终归并 63/64（TypeScript 32/32、Python 31/32）。同一输入、同一授权的 4 个对照在另一次采样中也都通过，无法把改善全部归因于权限调整。

剩余 `python-defect-11` 尝试执行原样例两条 unittest 命令以外的 Python 命令，被宿主拒绝。最终数值由独立解释器执行源码计算，另验目标和全量测试、脏文件及变更范围。两个动态数值参数可见于提示；当前证据支持这些输入与现有测试上的结果。

编码组含历史、诊断及复测共执行 83 次，Runtime 共记录 1,647,696 tokens。该计数不含其他业务组。

### 公网黄金业务

原 6 个黄金场景加 160 个业务变体，首采样通过数从 103/166 提升到 138/166。只给供应商瞬时故障一次重试后，两端分别为 **110/166 和 145/166**。最终业务变体 143/160，历史黄金场景按原 YAML 为 2/6，按工具、产物及业务结果独立验收为 4/6。加上两个历史编码场景，公网原 YAML 合计 **4/8**，独立业务验收 **6/8**。同一批历史 YAML 在确定性实现上为 **8/8**。

| 最终结果（含该类型的黄金历史场景） | 订单 | 合同 | 研究 | 验证修复循环 | 销售 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 公网通过数 | 33/34 | 32/33 | 32/33 | 15/33 | 33/33 |

最终 166 个业务回执的单项耗时中位数为 10.58 秒，P95 为 16.75 秒。编码历史两题各耗时约 51 秒、36 秒。跨轮复测的耗时之和没有用作整套评测的墙钟时间。

订单 A-999 被正确判为不存在，但答复未包含原 grader 指定的“未找到”。研究引用了实际来源，结论未采用“小规模试点”的固定措辞。合同输出符合三字段 Schema，风险评级为 medium，标注为 high。原 Loop 题只给“修复候选结果”，且要求固定文本 `candidate-fixed`，缺少可独立验证的候选及修复目标。四条历史失败全部保留。生成的 Loop 变体单独提供可检验任务，仍有未通过案例。

生成变体中，订单、合同、研究和销售分别通过 32/32。Loop 通过 15/32。17 个失败里，9 个候选已经与独立排序判据一致，文本验收仍未通过，最终耗尽修复预算；逐例回执未保存验证模型原文；7 个候选仍错且停止进展；1 个上游临时错误重试后仍失败。比如 `verified-repair-loop-02` 的候选与预期均为 `30,15,0,-2`，却被复核拒绝。后续应优先验证可确定判定任务的宿主验收路径，并与模型意见分别留痕。

销售把产物、工具结果和最终裸 JSON 分别校验。合同把既有输出合同提升至项目配置，研究将只读查询工具限定给 researcher，并验证 reviewer 实际看不到该工具。仅改提示词的中间研究方案曾退化到 12/33，保留了回执。公网黄金业务请求使用每次响应 512 tokens、单 Run 总预算 12,000、总时限 120 秒，保留原题原 grader。比较文件记录了每条输入、有效配置、预期、初次结果、重试与来源；最终 166 条中复用了 99 条有效配置相同的实测。

最后串行复跑了历史入口。Node 黄金与编码 18/18、持久任务测试 148/148、Python 销售测试、五个持久任务示例和跨进程 Python 同步/异步示例均通过。五域及补充历史验收前后均为 20/20，安装包消费者另测 17/17。并发阶段出现的超时保留在初次回执中，最终串行验证使用仓库原超时设置。

## 工程改动与剩余缺口

| 优先级 | 证据及处理 |
| --- | --- |
| High | Workflow 和 Loop 先插值再识别运算符，多行 FAIL 曾触发假成功。现从配置模板解析运算符，再分别插值。真实 YAML 探针还发现 switch 多行键被清理、空串命中后错误走默认分支，两条均已修复。 |
| High（评测可信度） | 固定 Flash 的验证预算曾吞掉全部有效结果。适配修复、重复对照与剩余失败见上表。 |
| High（可验收任务） | 生成的 Loop 任务有 9 个正确候选未通过文本验收。优先保留验证原文，再针对有明确业务判据的任务比较宿主验收与模型验收，同时检查错误放行率。 |
| Medium | 离线订单与研究模拟器写死历史订单或来源，研究工具零命中返回整个证据库。现在按真实工具结果回答、无匹配时返回空命中。 |
| Medium | 同一错误码曾把“阶段不存在”与“检查点不符合 Schema”合并，调用方无法定位问题。现保留兼容错误码，区分阶段与校验失败，并只返回宿主的 Schema 规则路径。 |
| Medium | 销售示例可把 NaN、无穷大或累计溢出写入 JSON。现用标准 JSON 的有限数约束，四条回归验证错误输入会保留原有有效文件。 |
| Medium | 合同离线模拟器固定返回高风险，编码模拟器依赖精确源码替换。合同受控结构校验 16/16，但其余 16 条只有 4 条符合预期。两种语言各有 16 个等价源码变体无法被固定补丁修复。保留这些失败，另行与公网模型结果比较。 |
| Medium | 原三轮资料整理尚无完整的逐轮应用判分。需要校验写出文件、引用、撤回、记忆和动作授权，不能只检查输入布局或另一套三轮任务。 |

工作流控制路径、注册扩展、检查点兼容性及重复执行具备直接验证证据。每种模型、供应商设置和任务语料均有自己的分母，本报告不据此推出生产环境的总体成功率。
