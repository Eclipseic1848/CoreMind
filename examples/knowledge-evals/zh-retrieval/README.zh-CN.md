# 中文资料检索固定集

松屿资料室、物件和规章均为本评测人工编写的合成资料。评测日期固定为 2026-10-01。输入包含手册和物件索引的两个版本，以及一份值班附页。资料含连续段落和 Markdown 表格。适合验证检索、权限、版本和引用，扫描件 OCR 的效果需另测。

## 资料与标注

索引输入只取 `sources/` 中的文件和 `manifest.json` 中的来源元数据。`validFrom` 当日起生效，`validUntil` 当日起失效，`null` 表示持续有效。`public` 身份可查看公开资料，`desk` 身份还可查看值班资料。

`cases.jsonl` 每行是一道题。有答案的 30 道题分别对应 30 条事实，覆盖原词、改写、编号、表格和版本冲突。`answer` 是参考短答，`evidence` 给出源文件名、从 1 开始的物理行号及可核对的原文摘录。表格引用指向具体数据行，检索器切块时应保留原文行号。给待测系统的输入是 `question`、`scope` 和固定日期。将答案和标注保留在评分端。

10 道无答案题中，6 道问资料未说明的事项，2 道只有过期版本提及，2 道所需内容超出当前读者权限。它们的答案和可采信证据均为 `null`。`decoy` 仅供评分端核对过期和受限的干扰项。

## 复跑

从本目录执行。校验脚本使用 Node 标准库。Python 基线依赖标准库 SQLite 启用 FTS5 扩展。

```sh
node check.mjs
python -X utf8 keyword_baseline.py
python -B -X utf8 test_keyword_baseline.py
```

第一条核对题目、来源、引文和三轮任务的标注。第二条运行离线 SQLite FTS5 关键词检索，逐条核对候选来源的权限和有效期。第三条向评分端传入过期和受限来源，验证它会报错。

真实模型复跑使用 OpenAI 兼容接口，不需要 Ollama：

```sh
DASHSCOPE_API_KEY=<key> python -B -X utf8 answer_benchmark.py --provider dashscope --model qwen-plus --model-dir <模型目录> --output <结果.json>
DEEPSEEK_API_KEY=<key> python -B -X utf8 answer_benchmark.py --provider deepseek --model deepseek-chat --model-dir <模型目录> --output <结果.json>
```

脚本先让模型生成答案与引文，再用独立审核步骤判断引文是否直接支持；不支持时最终拒答。密钥只通过环境变量传入。

P0 使用同一固定集在 Windows 和 Linux 容器复跑。30 道有答案题中，第一条命中 27 道，前五条命中 30 道。编号 Q21、Q25、Q26 的正确证据排在第二至第五位。10 道无答案题均得到相似片段。后续比较组件时应单独记录无依据问题的回答及其引文。

有答案题按前 5 个检索结果中是否包含标注的现行、可见来源及对应行计分。候选块覆盖多行时，应能从块内定位该摘录。生成回答再核对是否正确作答、引文是否支持回答。无答案题分别检查能否明确告知资料不足、有无虚构引文及越权内容。单纯返回相似片段的检索结果不能代替生成回答的拒答验收。

## 独立题集离线回放

`holdout-cases.jsonl` 沿用同一合成语料，单独保留 7 道有答案、6 道无答案的新题。包含现行版表格、改写题、失效资料，以及同一个问题在值班员与公开读者之间的权限对照。以下命令读取 `holdout-replay.json` 中人工录制的短答、引用位置和审核结果，索引只读取原文。运行需要 Python 标准库与 SQLite FTS5。

```sh
python -B -X utf8 answer_benchmark.py --replay --output knowledge.json
python -B -X utf8 -m unittest test_answer_benchmark
```

报告独立保存首条和前五条召回、短答文本、标注引文、审核后答案及明确拒答。正常夹具要求 7 道正例都进入前五条且答对并引对，6 道负例都明确拒答。未达标也会保存报告，退出码为 1。评分测试故意注入错引文和无依据断言。首条命中和无答案题的相似候选数量分别记录。

在回放命令上附加 `--model-dir <固定 BGE-M3 权重目录>`，可按本目录的 `requirements-retrieval.txt` 安装依赖后复跑稀疏 Qdrant 检索，回答及审核仍使用录制夹具。Windows 实测 FTS5 的首条 / 前五条命中为 6/7、7/7，稀疏 Qdrant 为 7/7、7/7。两种模式的正确短答与引文均为 7/7，明确拒答均为 6/6。结果用于核对检索与判分链路，真实模型表现需另行验证。

## 资料整理助手的三轮任务

`organize-materials.json` 固定同一读者的三个独立会话。执行时只向智能体传递本轮的 `input` 和可访问的资料。轮后按 `after` 顺序执行用户确认、偏好更正和来源撤回。期望答案、引文和动作约束留给评分端。

1. 对照两版流转索引，用比对 Skill 找齐七个新增编号，附二版引文，并用 `write` 生成 `summary.md`。一版只作为历史比较依据。检查文件实际内容和提交回执后，记录读者确认的表格偏好。
2. 开一个没有对话历史的新会话，改用工作手册查询咨询入口和补件时限。验收表格偏好能否随读者恢复、两个结论能否定位到新资料。随后将偏好改成要点列表，并撤回本轮手册。
3. 再开新会话查询仍有依据的受理窗口和已失去依据的补件时限。要求用列表回答，给窗口附出处，将时限标为资料不足。

同一夹具供 TypeScript、Python 和配置入口使用。本体关闭时直接整理资料，启用时再检查发布动作的前置条件和回执。使用替换后的对象和关系名称重复验证。模拟写入或发布成功后丢失回执时，核对已知状态并记录实际调用次数。

P0 用 `node check.mjs` 核对输入、标注和引用。P1 实跑导入与检索，P2 实跑记忆、撤回、Skill 和工具，P3 验证三轮组合以及本体开关和发布约束。
